## 部署 Hugo 博客 drafts.douzong.top (GitHub Pages)
- 仓库: github.com/ConataApple/drafts（public，main 分支存源码，gh-pages 分支存编译产物）
- 部署方式: 分支部署（gh-pages + GitHub Pages）。原因：钥匙串 PAT 只有 `repo` 权限，缺 `workflow` 权限，GitHub 硬性禁止用这种令牌推送 Actions 工作流文件。
- 发布脚本: 仓库根目录 `publish.sh`（从 Mac 钥匙串读 github.com/ConataApple 的 PAT，hugo 编译后 force-push 到 gh-pages）。用法：改完 content/ 下的 .md 后运行 `./publish.sh`。
- 自定义域已在 GitHub Pages 设置绑定 drafts.douzong.top（CNAME 文件随站点部署）。
- 待办（需 Olivia 操作）：阿里云 DNS 给 douzong.top 加 CNAME 记录 —— 主机记录=drafts，记录值=ConataApple.github.io；之后 GitHub 自动签发 HTTPS 证书。
- 坑：本版 Hugo 的 `hugo deploy` 部署目标 URL 里 `${GITHUB_TOKEN}` 不被展开（invalid userinfo），故改用 git 直推 gh-pages 的方案。
- 可选升级为「全自动（commit md 即更新）」：需一个带 workflow 权限的 PAT（fine-grained: Contents/Pages/Workflows RW），再补 .github/workflows/hugo.yml 并把 Pages 源切到 GitHub Actions。
